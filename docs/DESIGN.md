# DESIGN.md — the visual contract

Binding for all UI work. **The working prototype in `docs/reference/prototype/`
is the design**: its stylesheet (`assets/blueprint.css`) holds every value, and
its HTML shows every component. This file explains the rules behind it so you
can apply them to real content. If this file and the prototype disagree, stop
and ask the owner which one is right.

**Concept: Blueprint.** The site is a set of engineering drawings of one
person, treated as a system that gets revised over time. Revision 1.0 ships in
May 2027, when the degree finishes. Every page is a drawing sheet: bordered,
zoned, gridded, with a title block. The tone is bold and exact, with a dry
drafting joke or two. Dark only: there is no light theme and no theme toggle.

---

## Banned — never ship these

`npm run check:design` catches most of these automatically. The rest are on you.

- Any typeface other than Anybody. No Inter, Roboto, Geist, Space Grotesk,
  Instrument Serif, Fraunces, Poppins, Montserrat, Archivo, and no monospace
  font anywhere.
- Purple or lavender. Blue-to-purple gradients. Neon or acid-green accents.
- Gradients used as colour: washes, glows, text fills, button fills. (The grid
  pattern is built with `linear-gradient` stops ending in `transparent 1px`;
  that is the only allowed use.)
- `box-shadow`, `text-shadow`, `filter: blur()`, `backdrop-filter`, glass effects.
- Pure black (`#000`) or pure white (`#fff`).
- Rounded corners. Radius is `0` everywhere; the only circles are callout balloons.
- A coloured left or top border on cards. Rows of identical icon-topped cards.
- Stat banners and counters (years of experience, commits, stars).
- Emoji anywhere: UI, content or commit messages.
- Typewriter text, particles, cursor-following glow, custom cursors, 3D tilt on
  mouse move, loading screens, scroll hijacking, parallax, progress bars.
- Fake terminals, matrix rain, fake IDE windows, `⌘K` palettes.
- Skill bars, percentages or proficiency ratings. Skills are a parts list.
- GitHub contribution graphs and LeetCode widgets.
- Text that fades or slides in. Lines may draw in; text never animates in.
- Arrow glyphs (`→ ← ⟶`) in link or button text.
- Meta strings joined with middle dots (`A · B · C`).
- A single word in a heading accented with colour, weight or italic.
- Uppercase headings, buttons or sentences (see "Capitals" below).
- The words: passionate, seamless, leverage, cutting-edge, robust, innovative,
  crafted, journey, dive in, unlock, empower, elevate, synergy, world-class.
- Any image generated by AI, or any stock image, standing in for the owner's
  work.

## Color

Values are exact. Never approximate them or "adjust for balance".

```css
--ground:      #0F2350;  /* the sheet: deep cobalt blueprint paper */
--raised:      #16306A;  /* table heads, title-block headers, drawn boxes */
--deep:        #0B1B45;  /* figure backgrounds */
--plate-base:  #0A1A40;  /* the thickness layer under exploded parts */
--plate-on:    #1D3F85;  /* an exploded part while lifted */
--grid-major:  #27467E;  /* 100px grid (80px on mobile) */
--grid-minor:  #17336A;  /* 20px grid (16px on mobile) */
--line:        #7189BA;  /* hairlines, inner borders, table rules, ticks */
--chalk:       #E8EEF7;  /* primary text, heavy borders, drawn linework */
--dim:         #B4C3DE;  /* secondary text, labels, captions */
--amber:       #FFB547;  /* safety amber: live state, what's new, what's wrong */
```

- **Amber means "look here".** The current revision, anything new at that
  revision, the lifted part, known issues, the primary button, links, focus.
  Never decorative. If more than about 5% of a screen is amber, something is wrong.
- Two button styles only: primary is amber with `--ground` text; secondary is a
  1px chalk outline with chalk text.
- Hierarchy comes from surface steps (`ground` → `raised`) and line weight
  (2px chalk > 1.5px chalk > 1px line). Never shadows.
- The grid shows on the sheet everywhere except inside tables, title blocks and
  panels, which sit on solid `--ground` so text stays clean.

Contrast, verified:

| pair | WCAG 2.1 | APCA | allowed for |
|---|---|---|---|
| chalk on ground | 13.1:1 | Lc −93 | everything |
| chalk on raised | 10.8:1 | Lc −90 | everything |
| dim on ground | 8.6:1 | Lc −67 | secondary text 15px and up, labels |
| amber on ground | 8.7:1 | Lc −68 | text 13px bold and up, markers, state |
| ground on amber | 8.7:1 | Lc +68 | button labels 15px bold and up |
| line on ground | 4.4:1 | — | lines and borders only, never text |

## Type

One family: **Anybody** (variable, `wght` 100–900, `wdth` 50–150), self-hosted
at `public/fonts/anybody-latin.woff2` (latin subset, 56 KB, SIL Open Font
License, licence file alongside). Preload it:

```html
<link rel="preload" href="/fonts/anybody-latin.woff2" as="font" type="font/woff2" crossorigin>
```

Fallback stack: `"Anybody", "Arial Narrow", "Helvetica Neue", Arial, sans-serif`.
Width is the main expressive axis, set with `font-stretch`:

| role | class | size | stretch | weight | line-height |
|---|---|---|---|---|---|
| hero name | `.name` | fills its column, up to 260px | 60% | 800 | 0.82 |
| part title | `.part-head__title` | clamp(64px, 9vw, 136px) | 62% | 800 | 0.86 |
| sheet heading | `.t-sheet` | clamp(54px, 7vw, 88px) | 62% | 800 | 0.9 |
| revision headline | `.t-head` | clamp(26px, 2.7vw, 36px) | 75% | 700 | 1.1 |
| part heading | `.t-part` | clamp(24px, 2.2vw, 30px) | 75% | 800 | 1.05 |
| sub-heading | `.t-sub` | clamp(21px, 2vw, 26px) | 75% | 800 | 1.15 |
| lead | `.t-lead` | clamp(17px, 1.5vw, 20px), dim | 100% | 400 | 1.5 |
| body | `body` | 16–17px | 100% | 400 | 1.55 |
| drafting label | `.label` | 11px, tracking .14em, uppercase | 100% | 700 | 1.35 |

**The name fits its column automatically.** The name sits in `.name-box`
(a size container) and `.name` computes its size from `--chars`. Set
`style="--chars:N"` on `.name`, where N is the length of the longer of the first
and last name. Render first and last name as two `<span>`s. Do not change the
formula.

**Capitals belong to the drawing, sentence case belongs to the reader.**
Uppercase (via `text-transform`, never typed in content) is allowed only for
drafting vernacular: `.label`, the hero `.name`, table heads, group rows, form
labels, and text inside SVG drawings. Every heading, button, link and sentence
is sentence case. All numbers use `font-variant-numeric: tabular-nums` (set on
`body`). Body measure is 75 characters at most.

## The sheet — page anatomy

Every page is one drawing sheet (`.sheet`). Values are in the tokens.

- **Desktop:** 20px outer margin, 2px chalk border, 26px zone strips on all four
  sides (1–8 across top and bottom, A–H down the sides), then the drawing area
  with the grid. Content padding 48px.
- **Tablet (under 1024px):** padding 28px.
- **Mobile (under 768px):** 10px margin, 20px zone strips top and bottom only
  (1–4), no side strips, padding 18px. The nav collapses into a `<details>` menu.
- The masthead sits on solid ground with a 1px line under it: name, drawing
  number `DWG PF-2027-001`, nav links, and an amber "Email me".
- Sections are separated by 1px `--line` rules. Each starts with a drafting
  label (`Sheet 2 — Exploded view`, uppercased by CSS) then a sentence-case
  heading. Each sheet ends with a `.sheet-foot`.

## Components (all in the prototype)

**Title block** (`.tblock`). Cells of a drafting label over a value, 1px line
dividers, 1px chalk outer border. Hero: Drawn by, Program, Ships, Rev, Date,
Sheet. Part sheet: Part no., Rev, Role, Duration, Status, Users (only if
present), Material.

**Callout balloon.** 30px circle (26px mobile), 1.5px border, bold numeral,
joined to its target by a straight 1.5px leader line. Amber on figures.

**Dimension line.** 1px dim line, extension lines, 45° chalk ticks (never
arrowheads), and a label that states something true: the number of projects
(`9 RELEASES`, computed), `4 YEARS ± 0`.

**Tables** (`.table`): parts list, revisions, certifications, part history.
1px chalk outer border, `--raised` header row, 1px `--line` rules, solid ground.
Under 768px each row stacks into a block (the CSS does this). Group rows
(`tr.group`) carry stream names in amber labels.

**Release lines** (`.rl`). Every claim about work uses one of three markers.
The glyph carries the meaning, each has `role="img"` and an `aria-label`:

```
+   added — the outcome, with a number where one exists      (chalk)
~   changed — the decision, and what it replaced             (dim)
!   known issue — the limitation you would fix next          (amber)
```

**General notes** (`.gen-notes` on the home page, `.gnotes` on part sheets).
Numbered amber `1.` `2.` `3.`; on the home page each note is a bold chalk lead
and a dim remainder; on a part sheet each decision reads "Chose … instead of …
because …".

**More** (`details.more`). Extra outcomes inside a revisions row, closed by
default, summary "N more outcomes". Works without JS.

**Inspection report** (`.inspect`). Optional academics block under
certifications.

**Form** (`.form`). Labels above inputs, 1px chalk inputs on ground, amber
focus, status line in `[data-form-status]`, honeypot hidden with `.form__trap`.

**Stamp.** A 3px amber double rectangle rotated −9° inside FIG. 1 reading
`RELEASE PENDING / SHIPS MAY 2027`. Only visible at v1.0.

**Revision badge** (`.rev-badge`). Amber block, ground text, `REV 0.9`. Only in
the hero stamp row.

## Signature interaction 1: the revision scrubber

The centrepiece, in the hero under FIG. 1. Six stops from
`content/revisions.json`; the default is the current stop (v0.9).

- A native `<input type="range" id="rev-range">` with a `<label>`,
  `aria-valuetext` ("Revision 0.9, Year 4"), arrow-key support, plus a real
  `<button data-stop="i">` per stop (at least 44px tall), plus a polite live
  region.
- Moving it updates, together: the badge, era and status; the headline and bio;
  FIG. 1 (at level 0 a dashed "HELLO, WORLD" sketch on construction lines, then
  modules appear per level, new ones dashed amber, dimensions and notes at
  level 4); the title block's rev and date; the skills chips (new ones amber
  with `+`, future ones hidden); the exploded parts (future ones at 22%
  opacity, "Not built at vX"); the parts list rows (future dimmed, new ones
  "New in vX" in amber) and the "N of M releases built" count.
- At v1.0 the drawing matches v0.9 and the `RELEASE PENDING` stamp appears.
- Without JavaScript the page renders at the current stop and the controls stay
  `hidden`.
- The mechanics are all in `assets/scrubber.js`; its header lists the
  `data-` attributes the markup must carry. Keep them exactly.

## Signature interaction 2: the exploded parts view

The featured projects as an isometric exploded stack of plates.

- Geometry is in the CSS (`.parts` custom properties). Desktop: plates 340×220,
  205px apart, 10px thickness. Under 1024px: 220×140, 130px apart, 8px
  thickness, plate text scaled to 0.8. The stack height and positions derive
  from `--n` (number of plates) and `--i` (each plate's index). Do not change
  these values.
- **Content safe zone:** a lower plate is covered where the plate above overlaps
  it. On desktop keep plate content where local `x + y > 160`; the prototype
  puts the figure top-right and the text bottom-left for this reason.
- Each plate shows its project's schematic (a 148×104 SVG) — or a real
  screenshot cropped into that window — then `PART 0n`, the `plateTitle` or
  title, and the version.
- The labels beside the stack are the accessible links (to the part sheet). The
  plates are `aria-hidden` and mirror the hover.
- Hover or focus lifts a part (`translate(-40px, -16px)`, 300ms), brings it to
  the top and turns it amber; the spec panel beside the stack shows its summary,
  `+ ~ !` lines, material and "Open release notes".
- Under 1024px there is no hover: numbered buttons under the stack
  (`[data-pick]`, `aria-pressed`) choose the part.
- Without JavaScript every spec panel is visible, one after another.

## The four schematics

`grid` (a calendar or table of cells), `chart` (a line chart with an amber
dashed prediction), `nodes` (three connected circles), `pipeline` (three boxes
in a row). The plate versions are in the prototype's plates; the large version
for a part sheet's FIG. 3.1 is in `part.html` (the `grid` one). Draw the other
three large versions in the same style: chalk 1.5px lines, one amber element,
`--raised` fills, drafting labels in SVG text. Nothing else.

## Part sheets

`SHEET 3.n`, following `part.html`: header with the part title and title block;
the intro paragraphs; FIG. 3.1 (screenshot or large schematic) with numbered
amber callouts and a legend; "Inspect it yourself" buttons for the real links
only; release notes in three columns (Added, Changed, Known issues); general
notes (decisions); the revision table (history); previous and next sheet links.

## Motion

Lively, and every movement is a drawing movement. All of it is CSS; none of it
needs a script.

- **On load, once:** the hero hairline draws across (700ms), then FIG. 1 plots
  from left to right like a pen plotter (a `clip-path` sweep, 1.2s). Text is
  there from the first paint.
- **On scroll:** each section's top rule draws left to right as it enters, using
  CSS scroll-driven animation where the browser supports it. Elsewhere the rule
  is simply there. Rules only.
- **Scrubber:** opacity and stroke changes over 450ms, the track fill over 260ms.
- **Parts:** the lift over 300ms on `cubic-bezier(.2,.7,.2,1)`.
- **Hover** on links and buttons: colour only, 120ms. Nothing moves.
- `prefers-reduced-motion: reduce` turns all of it off.

## Voice

- Sentence case. Buttons say exactly what they do: "Email me", "Résumé (PDF)",
  "Open release notes", "Send message".
- Work is described in plain past tense with numbers: "Replaced brute-force
  search with constraint propagation once plans took 4 s."
- First person, or clipped sentences with no subject ("Generalist engineer
  with a lean toward ML and product."). Never the third person.
- The wit lives in the drafting frame: `NOTES: 1. ALL DIMENSIONS IN YEARS.
  2. DO NOT SCALE. 3. CAFFEINE NOT SHOWN.`, the `RELEASE PENDING` stamp, "Sign
  off on this release", "Your signature here". At most one dry line per sheet,
  never in the body copy. Ask the owner before adding a new one.
